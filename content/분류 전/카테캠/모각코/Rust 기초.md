
## Rust 특징
- 메모리 안전성: 가비지 컬렉터 없이도 메모리 오류(Null pointer, Buffer overflow 등) 방지
- 높은 성능: C/C++에 견줄 만한 실행 속도 제공
- 소유권(Ownership) 모델: Rust만의 독특한 메모리 관리 시스템

## 기본 문법
### Hello World
``` rust
fn main() {
  println!("hello");
}
```

Rust의 `main` 함수는 기본적으로 인자를 받지 않지만, `std::env::args`를 사용해서 cli 인자를 받을 수 있다.

``` rust
use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();
    
    // args[0]은 프로그램의 이름
    // args[1]부터 실제 전달된 인자가 들어온다.
    if args.len() > 1 {
        println!("첫 번째 인자: {}", args[1]);
    }
}
```

## 변수(Variables)와 상수(Constants)

Rust에서 데이터를 저장하는 방식은 변수와 상수로 나뉘며, 각각의 규칙은 다음과 같다.

### 1. 변수 (Variables: `let`)
변수는 프로그램 실행 중 값을 담는 공간이다.

- **기본 불변성**: `let`으로 선언된 변수는 기본적으로 불변(immutable)이다. 값이 한 번 할당되면 변경할 수 없다.
	- 기본적으로 불변으로 선언하여 data race가 발생할 수 있는 가변 상태를 최소화.
- **가변성 부여**: 값을 변경해야 한다면 `mut` 키워드를 사용한다. (`let mut x = 5;`)
- **초기화 규칙**:
    - 선언과 동시에 초기화하지 않아도 된다. 단, **사용하기 전에는 반드시 초기화**되어야 한다.
    - 초기화는 프로그램 실행 중(런타임)에 이루어질 수 있다.
- **타입 명시와 추론**:
    - **초기값이 있는 경우**: 컴파일러가 값을 보고 타입을 추론하므로 타입 명시를 생략할 수 있다.
    - **초기값이 없는 경우**: 컴파일러가 타입을 추론할 근거가 없으므로 **반드시 타입을 명시**해야 한다. (`let x: i32;`)

### 2. 상수 (Constants: `const`)
상수는 프로그램 전체에서 변하지 않는 고정된 값을 정의할 때 사용한다.

- **항상 불변**: `mut` 키워드를 사용할 수 없으며, 선언 후 값을 변경하는 것이 불가능하다.
- **타입 명시 필수**: 초기값 유무와 관계없이 상수는 반드시 타입을 명시해야 한다. (`const MAX_POINTS: u32 = 100_000;`)
- **컴파일 타임 결정**: 상수는 컴파일 시점에 값이 결정되어야 한다. 따라서 함수 호출 결과나 런타임에 계산되는 값은 대입할 수 없다.
- **명명 규칙**: 관례적으로 모든 글자를 대문자로 쓰고, 단어 사이를 밑줄(`_`)로 구분한다. (예: `MAX_SPEED`)

### 3. 비교 요약표

| 특징 | 변수 (`let`) | 상수 (`const`) |
| :--- | :--- | :--- |
| **키워드** | `let` | `const` |
| **가변성** | `mut` 사용 시 가능 | 절대 불가능 |
| **타입 명시** | 초기값 없으면 필수 | **항상 필수** |
| **값 결정 시점** | 런타임 | 컴파일 타임 |
| **초기화** | 선언 후 나중에 가능 | 선언과 동시에 필수 |

### 4. 코드 예시
```rust
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;

fn main() {
    // 초기값이 있는 변수 (타입 추론)
    let x = 5; 
    
    // 초기값이 없는 변수 (타입 명시 필수)
    let y: i32;
    y = 10;
    
    // 가변 변수
    let mut z = 15;
    z = 20; 
    
    println!("상수: {}, 변수: {}, {}, {}", THREE_HOURS_IN_SECONDS, x, y, z);
}
```

## 4. 데이터 타입 (Data Types)

**Rust는 정적 타입(Statically Typed) 언어**이므로, 컴파일 타임에 모든 변수의 타입을 알아야 한다.

### 4.1 기본 타입 (Primitive Types)
#### 4.1.1 스칼라 타입 (Scalar Types)
단일 값을 표현하며, 컴파일 타임에 크기가 고정되어 스택(Stack)에 할당된다.

- **정수형 (Integer)**: 
    - 부호 유무(`i`/`u`)와 비트 크기(`8`, `16`, `32`, `64`, `128`)로 세분화된다.
    - `isize`/`usize`: 아키텍처(32/64-bit)에 의존하는 포인터 크기 타입.
    - **특징**: 오버플로우 발생 시 디버그 모드에서 `panic`을 발생시켜 안전성을 보장한다.
![[Pasted image 20260629110039.png]]

		isize와 usize는 동작되는 컴퓨터의 CPU와 운영체제가 몇 비트인가에 따라 결정되는 변수.
	
- **부동 소수점 (Floating-point)**: `f32`, `f64`(기본값). IEEE 754 표준을 준수한다.
	![[Pasted image 20260629111020.png]]
	Rust에서 소숫점이 있는 값에 대한 디폴트는 `f64`다.
- **불리언 (Boolean)**: `bool` (1바이트).
- **문자 (Character)**: `char` (4바이트). 유니코드 스칼라 값을 저장하며, ASCII만 다루는 C의 `char`와 달리 전 세계 문자를 표현한다.
### 4.1.2 복합 타입 (Compound Types)

복합 타입은 여러 값을 하나의 타입으로 묶어 표현하며, 모든 요소가 **컴파일 타임에 크기가 결정(Sized)**되어야 한다는 공통점이 있다.

#### 1. 튜플 (Tuple)
- **정의**: 고정된 길이의 데이터 묶음으로, 각 요소의 타입이 서로 달라도 되는 **이질적(Heterogeneous) 컨테이너**이다. (물론 같은 타입끼리 묶는 것도 가능하다.)
- **메모리 레이아웃**: 필드들이 메모리에 연속적으로 배치된다. 구조체와 달리 필드명이 없으므로 인덱스(`.0`, `.1` 등)로 접근한다.
- **타입 시스템**: 튜플의 타입은 각 요소 타입의 순서 있는 집합으로 정의된다. 예를 들어 `(i32, i32)`와 `(i32, f64)`는 완전히 다른 타입이다.
- **용도**: 주로 함수에서 여러 값을 반환하거나, 서로 다른 타입의 데이터를 일시적으로 묶을 때 사용한다.
- **특징**: 튜플 자체의 크기는 각 요소 타입의 크기 합과 패딩(Padding)을 고려하여 컴파일 타임에 결정된다.

#### 2. 배열 (Array)
- **정의**: 동일한 타입의 값을 고정된 길이로 묶은 연속적인 메모리 블록이다.
- **선언 및 초기화**:
    - `let a: [i32; 5] = [1, 2, 3, 4, 5];` (명시적 선언)
    - `let b = [0; 5];` (동일한 값으로 5개 초기화)
- **메모리 레이아웃**: 스택에 `[T; N]` 크기만큼 연속적으로 할당된다.
- **안전성 (Bounds Checking)**:
    - C/C++과 달리, Rust는 인덱스 접근 시 **런타임 경계 검사(Bounds Checking)**를 수행한다.
    - 인덱스가 범위를 벗어나면 프로그램은 즉시 `panic`을 발생시켜 메모리 오염(Buffer Overflow)을 방지한다.
    - **최적화**: 컴파일러는 루프 내에서 인덱스 범위를 벗어나지 않음이 증명되면, 런타임 검사 코드를 제거하여 성능 저하를 최소화한다.

#### 왜 배열의 크기는 컴파일 타임에 고정되어야 하는가?
Rust에서 배열(`[T; N]`)의 크기 `N`은 타입의 일부이다. 즉, `[i32; 3]`과 `[i32; 4]`는 **서로 다른 타입**으로 간주된다. 이는 컴파일러가 스택 프레임의 크기를 정확히 계산하기 위함이다. 만약 크기가 런타임에 결정되어야 한다면, 배열 대신 힙에 할당되는 `Vec<T>`를 사용해야 한다.

#### 튜플과 배열의 메모리 할당
- **튜플**: `(i32, f64)`는 `i32`와 `f64`를 합친 크기만큼 스택을 점유한다.
- **배열**: `[i32; 5]`는 `4바이트 * 5 = 20바이트`를 스택에 점유한다.

### 4.2 표준 라이브러리 타입 (Standard Library Types)

스칼라/복합 타입 외에 Rust 표준 라이브러리(`std`)에서 제공하는, 힙(Heap) 메모리를 사용하는 가변 크기 타입들.

- **`String`**:
    - UTF-8 인코딩된 가변 길이 문자열.
    - `&str`(문자열 슬라이스)과 달리 소유권을 가지며, 힙에 데이터를 저장한다.
- **`Vec<T>` (Vector)**:
    - 동일한 타입의 값을 가변적으로 담을 수 있는 리스트.
    - 배열과 달리 런타임에 크기를 늘리거나 줄일 수 있다.
- **`Option<T>`**:
    - 값이 있을 수도, 없을 수도 있는 상황을 표현하는 열거형(Enum).
    - `Some(T)` 또는 `None`을 가지며, `null` 포인터 오류를 원천 차단한다.
- **`Result<T, E>`**:
    - 성공(`Ok(T)`) 또는 실패(`Err(E)`)를 나타내는 에러 처리용 열거형.
    - 예외(Exception) 대신 명시적인 에러 핸들링을 강제한다.
- **`Box<T>`**:
    - 데이터를 힙에 할당하고, 스택에는 해당 데이터를 가리키는 포인터만 저장하는 스마트 포인터.
    - 재귀적 데이터 구조나 큰 데이터를 스택 오버플로우 없이 전달할 때 사용한다.

### 4.3 메모리 할당 모델 (Memory Layout)
데이터의 타입은 해당 데이터가 메모리의 어디에 위치할지 결정한다.

| 구분 | 스택 (Stack) | 힙 (Heap) |
| :--- | :--- | :--- |
| **할당 대상** | 스칼라, 튜플, 고정 크기 배열 | `String`, `Vec<T>`, `Box<T>` 등 |
| **크기 결정** | 컴파일 타임 (고정) | 런타임 (가변) |
| **관리 방식** | 함수 호출/종료 시 자동 해제 | 소유권(Ownership) 규칙에 의해 해제 |
| **성능** | 매우 빠름 (LIFO) | 상대적으로 느림 (간접 참조) |

### 4.4 C 언어와의 핵심 차이점
1. **암시적 형변환 불가**: Rust는 서로 다른 타입 간의 연산을 허용하지 않는다. 반드시 `as` 키워드로 명시적 형변환(Casting)을 해야 한다.
2. **안전성 우선**: C는 성능을 위해 경계 검사를 생략하지만, Rust는 안전성을 위해 런타임 검사를 수행한다. (단, 컴파일러 최적화를 통해 오버헤드를 최소화함)
3. **문자열 처리**: C의 `char`는 1바이트 정수형에 가깝지만, **Rust의 `char`는 유니코드 문자를 보장하는 독립적인 타입**이다.
4. **Null 부재**: Rust는 `null` 대신 `Option<T>`를 사용하여 값이 없는 상태를 타입 시스템 내에서 안전하게 관리한다.

## 5. 함수와 제어 흐름 (Functions & Control Flow)

### 5.1 함수 (Functions)
Rust는 `fn` 키워드로 함수를 정의하며, 모든 파라미터와 반환값의 타입을 명시해야 한다.

- **구문(Statement) vs 표현식(Expression)**:
    - **구문**: 값을 **반환하지 않는** 명령 (예: `let x = 5;`)
    - **표현식**: **값을 평가하여 반환**하는 코드 (예: `5 + 6`)
- **반환값**: 함수 본문의 마지막 표현식은 `return` 키워드 없이 자동으로 반환된다. (세미콜론 `;`을 붙이면 구문이 되어 반환되지 않음에 주의)

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b // 마지막 줄에 세미콜론이 없으면 반환값으로 취급
}
```

### 5.2 제어 흐름 (Control Flow)

#### 1. `if` 표현식
Rust의 `if`는 문(Statement)이 아니라 **표현식(Expression)**이다. 따라서 `if`의 결과를 변수에 할당할 수 있다.

```rust
let number = if condition { 5 } else { 6 }; // 삼항 연산자 대신 사용
```
*주의: `if`와 `else` 블록의 반환 타입은 반드시 일치해야 한다.*

#### 2. 반복문 (Loops)
- **`loop`**: 무한 루프. `break`를 통해 값을 반환할 수 있다.
- **`while`**: 조건이 참인 동안 반복.
- **`for`**: 컬렉션의 요소를 순회. (가장 안전하고 권장되는 방식)

```rust
let result = loop {
    counter += 1;
    if counter == 10 { break counter * 2; } // 루프의 결과값을 반환
};
```

### 5.3 스코프(Scope)와 블록 표현식
Rust에서 `{ }` 블록은 그 자체로 하나의 **표현식**이다. 블록 내부의 마지막 표현식이 블록 전체의 값이 된다.

```rust
let y = {
    let x = 3;
    x + 1 // y는 4가 됨
};
```

### [전공자 관점의 핵심 포인트]

1. **표현식 지향 설계 (Expression-oriented)**:
   - C/Java는 `if`나 `loop`가 값을 반환하지 않는 '문(Statement)'이지만, Rust는 거의 모든 것이 '표현식(Expression)'이다. 이는 함수형 프로그래밍의 특성을 차용하여, 변수 초기화 시 불필요한 가변 변수(`mut`) 선언을 줄이고 불변성을 유지하기 위함이다.

2. **타입 안전성**:
   - `if`의 각 분기(Branch)는 반드시 동일한 타입을 반환해야 한다. 컴파일러는 이를 통해 런타임에 발생할 수 있는 타입 불일치 오류를 원천 차단한다.

3. **제어 흐름과 소유권**:
   - 제어문 블록은 새로운 스코프를 생성한다. 이 스코프가 종료될 때, 해당 블록 내에서 생성된(소유권을 가진) 변수들은 자동으로 `drop`되어 메모리가 해제된다. 이것이 Rust가 가비지 컬렉터 없이 메모리를 관리하는 기초가 된다.
