# 순수 함수 (Pure Function)

순수 함수는 컴퓨터 프로그래밍에서 **부수 효과(Side Effect)가 없는 함수**를 의미하며, 수학적 함수(Mathematical Function)의 개념을 프로그래밍 언어에 그대로 투영한 것이다.

컴퓨터공학 관점에서 어떤 함수가 순수 함수로 정의되기 위해서는 다음 두 가지 핵심 성질을 반드시 만족해야 한다.

---

## 0. 순수 함수의 두 가지 필수 조건

### ① 참조 투명성 (Referential Transparency)

**동일한 입력(Argument)에 대해 항상 동일한 출력(Return Value)을 반환하는 성질**이다.

- 함수의 결과가 오직 전달받은 인자에 의해서만 결정된다.
- 함수 외부의 가변 상태(Mutable State), 전역 변수, 시스템 시간, 난수(Random Number) 등에 의존하지 않는다.
- **CS적 의미:** 프로그램 내에서 함수 호출 식을 그 결과값으로 완전히 대체(Replace)하더라도 프로그램의 전체적인 동작과 의미가 변하지 않는다. 이는 컴파일러 최적화(예: Memoization, Constant Folding)를 가능하게 하는 핵심 기반이 된다.

### ② 부수 효과 부재 (No Side Effects)

**함수를 평가(Evaluation)하는 과정에서 외부 세계의 상태를 변경하지 않는 성질**이다.

- 함수 외부의 메모리(Heap 영역, 전역 변수 등)를 수정하지 않는다.
- 파일 시스템 쓰기, 네트워크 요청, 콘솔 출력, 실제 DOM 조작 등 외부 I/O 디바이스와의 상호작용을 발생시키지 않는다.
- **CS적 의미:** 함수의 실행이 시스템의 전역 상태(Global State)에 어떠한 흔적도 남기지 않는다.

## 1. PL 관점에서의 Side Effect와 Expression/Statement

프로그래밍 언어론(Programming Languages)에서 **Side Effect(부수 효과)** 와 **Expression(식) / Statement(문)** 의 관계를 이해하기 위해서는, 먼저 각 개념의 본질적인 존재 목적과 패러다임에 따른 관점 차이를 명확히 해야 한다.

### ① 'Side(부수적)'의 상대성: Main Effect vs Side Effect
컴퓨터공학에서 'Side Effect'는 **"주된 목적(Main Effect) 외에 부수적으로 발생하는 상태 변경"** 을 의미한다. 무엇을 프로그램의 주된 목적으로 보느냐에 따라 부수 효과의 범주가 달라진다.

- **명령형 패러다임 (Imperative Programming):**
	- 프로그램의 주 목적은 순차적인 명령을 실행하여 메모리 상태를 변경하는 것이다.
	- 따라서 **Statement(문)를 통해 메모리를 변경하는 것은 Main Effect(주 효과)** 에 해당하며, 값을 계산하는 **Expression(식)이나 함수가 예외적으로 메모리를 변경할 때만 Side Effect(부수 효과)** 라고 부른다.

- **함수형/선언적 패러다임 (Functional/Declarative Programming):**
	- 프로그램의 주 목적은 오직 값을 계산하여 반환하는 것이다.
	- 따라서 값을 계산하는 행위 외에 **외부 상태(메모리)를 변경하는 모든 행위(Write 연산)를 문과 식의 구분 없이 전부 Side Effect**로 규정한다. 리액트 역시 이 관점을 따른다.

---

### ② Expression(식)과 Statement(문)의 본질적 차이
식과 문을 구별하는 기준은 Side Effect의 유무가 아니라, **"평가(Evaluation)되어 값을 반환하는가"** 이다. 이 두 개념과 Side Effect의 유무는 다음과 같이 분류할 수 있다.

| 구분 | Side Effect 없음 (Pure) | Side Effect 있음 (Impure) |
| --- | --- | --- |
| **Expression (식)** | `a + b`<br>`x > 5`<br>(값만 반환하고 메모리 변경 없음) | `x++` (값 반환 + `x` 메모리 변경)<br>`y = 10` (대입 식, `10` 반환 + `y` 메모리 변경) |
| **Statement (문)** | `break;`<br>`continue;`<br>(제어 흐름만 변경하고 메모리 변경 없음) | `let x = 5;` (변수 선언 및 대입)<br>`if (x > 5) { ... }` (조건에 따른 실행) |

---

### ③ 함수(Function)와 Side Effect의 관계
<span style="background:rgba(240, 200, 0, 0.2)">함수는 수학적 개념에서 유래했기 때문에 본질적으로 **Expression(식)** 의 성격을 지닌다. 즉, 인자를 받아 결과값을 반환하는 것이 주 목적(Main Effect)이다.</span>

따라서 함수가 실행되는 과정에서 외부 메모리 영역(전역 변수, 힙 영역의 객체, 실제 DOM 등)에 Write 연산을 수행하는 것은 함수의 주 목적을 벗어난 **Side Effect**로 규정된다. 

순수 함수는 이러한 Side Effect가 완전히 배제되어, 오직 **"입력에 따른 결과값 반환"**이라는 본질(참조 투명성)만 남긴 함수를 의미한다.

---

## 2. Local Mutation vs Non-local Mutation (지역적 가변성 vs 비지역적 가변성)

함수가 본질적으로 식(Expression)이라면, <span style="background:rgba(240, 200, 0, 0.2)">함수 내부에서 발생하는 모든 Write(쓰기) 연산은 순수성을 깨뜨리는가? 그렇지 않다. </span>물리적 메모리 관점에서 Write 연산이 발생하는 **스코프(Scope)와 생명주기(Lifecycle)에 따라 순수성 유지 여부가 결정된다.**

---

### ① Local Mutation (지역적 쓰기): 순수성 유지
함수 내부의 **스택 프레임(Stack Frame)** 안에서만 일어나는 메모리 쓰기 연산이다.

- **메모리 구조적 특징:** 함수가 호출될 때 스택 영역에 할당되는 지역 변수들은 함수가 <span style="background:rgba(240, 200, 0, 0.2)">반환(Pop)되는 순간 메모리에서 완전히 소멸</span>한다.
- **관측 가능한 순수성 (Observational Purity):** 외부의 관찰자(Caller) 관점에서는 함수 내부에서 어떤 가변(Mutation) 행위가 일어났는지 절대 알 수 없다. 오직 입력값과 최종 출력값만 관측할 수 있을 뿐이다.
- **결론:** 외부 상태를 전혀 오염시키지 않으므로, 내부적으로 아무리 많은 Write 연산이 발생하더라도 이 함수는 **순수 함수**다.

#### 코드 예시 (반복문을 통한 팩토리얼 계산)
```javascript
function factorial(n) {
  let result = 1; // Local Write (스택 프레임 내부)
  for (let i = 2; i <= n; i++) {
    result *= i;  // Local Mutation (외부에서 관측 불가)
  }
  return result;  // 동일한 n에 대해 항상 동일한 결과 반환
}
```

---

### ② Non-local Mutation (비지역적 쓰기): 순수성 파괴 (Side Effect)
함수 외부의 메모리 공간인 **전역 스코프(Global Scope)**나 **힙(Heap) 영역**에 존재하는 공유 메모리에 Write 연산을 수행하는 것이다.

- **메모리 구조적 특징:** 함수가 <span style="background:rgba(240, 200, 0, 0.2)">반환된 후에도 변경된 메모리 상태가 유지</span>되며, 다른 함수나 프로세스가 이 메모리 영역을 참조할 수 있다.
- **참조 투명성 파괴:** 외부 상태에 의존하여 쓰기 연산을 수행하므로, 동일한 인자를 전달하더라도 외부 상태의 변화에 따라 함수의 반환값이 달라질 수 있다. 또한, 멀티스레드 환경에서는 경쟁 상태(Race Condition)를 유발한다.
- **결론:** 외부 세계에 영구적인 흔적을 남기는 행위이므로, 이는 순수성을 깨뜨리는 **Side Effect**다.

#### 코드 예시 (전역 변수 및 참조형 인자 수정)
```javascript
// 예시 1: 전역 변수 수정 (Global Scope Write)
let total = 0;
function accumulate(x) {
  total += x; // Non-local Mutation! (Side Effect 발생)
  return total;
}

// 예시 2: 참조형 인자 수정 (Heap Area Write)
function updateAge(user) {
  // 자바스크립트는 객체를 Call by Sharing으로 전달하므로, 
  // user 객체의 프로퍼티를 수정하면 힙 영역의 원본 데이터가 변경된다.
  user.age += 1; // Non-local Mutation! (부모 컴포넌트의 상태 오염)
  return user;
}
```

## 💡 정리


> [!NOTE] summary
> 1. **식(Expression)과 문(Statement)의 구분**은 '값의 반환 여부'일 뿐이며, 두 형태 모두 Side Effect를 가질 수도 있고 가지지 않을 수도 있다.
> 
> 2. **함수는 본질적으로 식(Expression)**이므로, 수학적 함수와 같이 외부 세계에 영향을 주지 않고 오직 동일한 입력에 따른 동일한 출력만을 반환해야 한다.
> 
> 3. **Local Mutation**은 함수가 실행되는 동안에만 임시로 존재하는 스택 메모리 내에서의 닫힌 연산이므로 **안전하며, 함수의 순수성을 해치지 않는다.**
> 
> 4. **Non-local Mutation**은 함수 외부의 공유 메모리(Heap, Global)를 오염시키는 열린 연산이므로 **위험하며, 순수성을 깨뜨리는 Side Effect의 본질이다.**
