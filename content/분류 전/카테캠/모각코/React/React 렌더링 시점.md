
리액트의 렌더링 프로세스는 다음 세 단계로 나누어 볼 수 있다.

1. **Trigger (트리거):** 상태 변화에 의해 렌더링 작업을 스케줄링하는 단계다.

2. **Render phase (렌더 단계):** 컴포넌트를 호출하여 가상 DOM을 생성하고 변경 사항을 계산하는 단계다.

3. **Commit phase (커밋 단계):** 계산된 변경 사항을 실제 DOM에 반영하는 단계다.

---

## 1. Trigger (트리거 단계)
리액트 엔진이 렌더링 작업을 큐(Queue)에 등록하는 단계다. 리액트에서 렌더링이 발생하는 원인은 오직 다음 **두 가지**뿐이다.

- **최초 렌더링 (Initial Render):** 애플리케이션 진입 시 루트 노드(`createRoot`)가 마운트될 때 발생한다.
- **상태 업데이트 (Re-render):** 컴포넌트의 상태(State)가 변경될 때 발생한다.
    - **자체 상태 변경:** `useState`의 setter 함수나 `useReducer` 등의 dispatch가 호출되어 컴포넌트 자체의 상태가 변하는 경우다.
    - **상태 변경의 전파:** 부모 컴포넌트의 상태가 변경되어 부모가 재렌더링되면, 하위 자식 컴포넌트들 역시 기본적으로 재렌더링이 트리거된다. (Context API의 값 변경도 이 범주에 속한다.)

---

## 2. Render phase (렌더 단계)
컴포넌트 함수를 실행하여 새로운 가상 DOM 트리를 형성하고, 이전 트리와 비교하여 변경된 요소를 찾아내는 단계다.

- **Reconciliation (재조정):** 리액트는 휴리스틱 알고리즘($O(N)$)을 사용하여 이전 가상 DOM 트리와 신규 가상 DOM 트리를 비교(Diffing)한다.
- **Fiber Architecture:** 리액트 16부터 도입된 Fiber 엔진은 이 단계를 잘게 쪼개어(Work-in-progress) 실행할 수 있다. 우선순위에 따라 작업을 일시 중단(Pause), 재개(Resume), 혹은 폐기(Discard)할 수 있는 비동기적 특성을 가진다.
- **Side Effect Free:** 이 단계는 순수 함수처럼 동작해야 하며, 어떠한 부수 효과(Side Effect)도 발생시켜서는 안 된다. 실제 DOM에 접근하지 않는 메모리 상의 연산이기 때문이다.

---

## 3. Commit phase (커밋 단계)
렌더 단계에서 계산된 차이점(Effect List)을 실제 브라우저의 DOM에 동기적으로 반영하는 단계다.

- **DOM Manipulation:** `appendChild`, `removeChild` 등 실제 DOM API를 호출하여 트리를 업데이트한다.
- **Synchronous Execution:** 렌더 단계와 달리 커밋 단계는 중간에 중단될 수 없으며, 일관된 화면을 보여주기 위해 동기적(Synchronous)으로 일괄 처리된다.
- **Lifecycle/Hooks:** DOM 반영 직후 `useLayoutEffect`가 동기적으로 실행되며, 이후 브라우저가 화면을 그린(Paint) 뒤 `useEffect`가 비동기적으로 실행된다.

## 💡 CS 관점에서의 핵심 Insight

### 1. 렌더링(Rendering)과 페인팅(Painting)의 분리
- 리액트의 '렌더링'은 브라우저가 화면을 그리는 '페인팅(Reflow/Repaint)'과 엄격히 구분된다. 렌더링은 메모리 상에서 가상 DOM 트리를 연산하는 과정에 불과하다.
- 따라서 렌더 단계가 실행되었다고 해서 반드시 브라우저의 레이아웃 엔진이 구동되는 것은 아니다. 변경 사항이 없다면 커밋 단계는 생략된다.

### 2. 성능 병목의 본질과 최적화 전략
- 자바스크립트 엔진의 메모리 연산(Render phase)은 매우 빠르다. 진짜 병목은 브라우저 렌더링 엔진의 레이아웃 계산 및 페인팅 과정(Commit phase 이후)에서 발생한다.
- 리액트의 조정 알고리즘이 불필요한 DOM 조작을 방지해 주지만, 가상 DOM을 만드는 연산 자체도 컴포넌트 트리가 커지면 비용이 된다.
- 따라서 프론트엔드 성능 최적화의 핵심은 **"아예 계산할 필요가 없는 하위 컴포넌트의 Render phase 진입을 막는 것"**이다. `React.memo`를 통한 얕은 비교(Shallow Compare)나 `useMemo`, `useCallback`을 통한 참조 동일성 유지는 결국 Render phase 자체를 스킵하기 위한 도구다.
