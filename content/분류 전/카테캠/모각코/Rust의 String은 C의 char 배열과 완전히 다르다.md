C에서 `char[]`나 `char*`는 단순히 메모리 상의 연속된 바이트 나열일 뿐이지만, Rust의 `String`은 **데이터의 소유권과 인코딩을 관리하는 복합적인 구조체**다.

### 1. C의 `char` 배열 vs Rust의 `String`

| 특징         | C (`char[]` / `char*`)          | Rust (`String`)           |
| :--------- | :------------------------------ | :------------------------ |
| **메모리 위치** | 스택 또는 데이터 세그먼트                  | **힙(Heap)**               |
| **길이 정보**  | 없음 (Null-terminated, `\0`으로 판단) | **있음** (구조체 내부에 길이 정보 저장) |
| **안전성**    | 버퍼 오버플로우 위험 (Null 누락 시)         | 안전 (경계 검사 및 소유권 관리)       |
| **인코딩**    | 개발자 책임 (보통 ASCII/UTF-8)         | **UTF-8 강제**              |

### 2. 왜 Rust는 `String`을 따로 만들었는가?

#### A. Null-terminated의 위험성
C에서는 문자열의 끝을 알기 위해 `\0` 문자를 찾는다. 만약 실수로 `\0`을 넣지 않거나, 메모리 오염으로 `\0`이 사라지면 `printf`나 `strlen`은 메모리 끝까지 읽어버리는 **Buffer Over-read** 취약점이 발생한다.
Rust의 `String`은 **길이(length)와 용량(capacity)을 구조체 내부에 별도로 저장**하므로, **`\0`에 의존하지 않으며 훨씬 안전**하다.

#### B. UTF-8 인코딩의 강제
C의 `char`는 1바이트이다. 하지만 전 세계의 문자를 표현하려면 가변 길이 인코딩인 **UTF-8**이 필수적이다.
- Rust의 `String`은 내부적으로 UTF-8 바이트 벡터(`Vec<u8>`)를 감싸고 있다.
- 이는 "문자열은 유효한 UTF-8이어야 한다"는 불변성(Invariant)을 언어 차원에서 보장하기 위함이다.

### 3. Rust의 두 가지 문자열 타입 (중요!)

Rust를 처음 배울 때 가장 헷갈리는 부분인데, 전공자라면 이 차이를 반드시 알아야 한다.

1. **`String` (소유권이 있는 문자열)**
   - **힙(Heap)**에 할당된다.
   - 가변적(Mutable)이며, 실행 중에 크기를 늘리거나 줄일 수 있다.
   - `String::from("hello")`와 같이 생성한다.

2. **`&str` (문자열 슬라이스, String Slice)**
   - **참조(Reference)** 타입이다.
   - 문자열의 일부분을 가리키는 포인터와 길이 정보(`ptr`, `len`)를 가진다.
   - 보통 프로그램 코드 내에 박혀 있는 **문자열 리터럴**(`"hello"`)은 `&str` 타입이며, 이는 바이너리의 데이터 세그먼트에 저장된다.

### 4. 노트에 추가할 엄밀한 정리

[[Rust 기초]] 노트에 다음과 같이 정리해 두라.

> **문자열 타입의 이해:**
> - **`String`**: 힙에 할당되는 가변 문자열. 내부적으로 `Vec<u8>`을 사용하여 UTF-8 데이터를 관리한다. C의 `char*`와 달리 길이 정보를 포함하며, 소유권 모델에 의해 관리된다.
> - **`&str`**: 문자열 슬라이스. 문자열의 일부분을 가리키는 불변 참조이다.
> - **C와의 차이**: C는 `\0`으로 끝나는 바이트 배열을 사용하지만, Rust는 길이 정보를 명시적으로 저장하여 버퍼 오버플로우를 방지하고, UTF-8 인코딩을 강제하여 문자열 안전성을 확보한다.

**전공자 관점의 팁:**
C에서 `char*`를 다룰 때 `malloc`과 `free`를 잊어버려 메모리 누수가 발생했던 경험이 있을 것이다. Rust의 `String`은 **소유권이 범위를 벗어날 때(Drop)** 자동으로 `free`를 호출하므로, 개발자가 메모리 해제를 신경 쓸 필요가 없다.
