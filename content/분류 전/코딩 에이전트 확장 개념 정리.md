# 코딩 에이전트 확장 개념 정리

코딩 에이전트에 붙는 확장 요소들은 결국 다음 세 가지 중 하나로 동작한다.

1. **LLM 컨텍스트에 정보를 넣는다.**
2. **LLM이 호출할 수 있는 도구를 제공한다.**
3. **LLM 바깥의 런타임이 특정 시점에 자동으로 개입한다.**

Codex 기준으로 보면 `AGENTS.md`, Skills, MCP, Hooks, Plugins, Memories, Rules/Permissions, Subagents, Automations 등이 이 역할을 나눠 가진다.

## 전체 분류

| 개념 | 주 역할 | LLM에 들어가는 방식 | 실행 판단 주체 |
|---|---|---|---|
| `AGENTS.md` | 지속 지침 | 세션 시작 시 instruction context로 주입 | Codex 런타임 |
| Skills | 재사용 워크플로우 | 처음엔 metadata만, 선택 후 `SKILL.md` 본문 주입 | 사용자 또는 LLM |
| MCP | 외부 도구/데이터 연결 | tool schema 노출, 호출 결과를 context로 주입 | LLM이 호출 판단, Codex가 실행 |
| Hooks | lifecycle 자동화 | 보통 직접 주입되지 않음. 필요 시 결과가 context에 반영 | Codex 런타임 |
| Plugins | 배포 패키지 | 포함된 skill/MCP/hook/app이 각각 등록됨 | Codex 런타임 |
| Memories | 이전 작업 기억 | 관련 memory가 세션 context로 주입 | Codex 런타임 |
| Rules/Permissions | 권한/정책 통제 | 주로 런타임 정책으로 사용 | Codex 런타임 |
| Subagents | 역할 분리된 별도 에이전트 | 별도 LLM 세션에 별도 instruction/tool 설정 제공 | 사용자의 명시 요청 |
| Automations | 예약 실행 | 예약된 prompt로 새 agent run 또는 thread wake-up 실행 | 스케줄러/Codex 런타임 |
| Custom prompts | 프롬프트 매크로 | 호출 시 텍스트로 확장되어 prompt에 들어감 | 사용자 |

## AGENTS.md

`AGENTS.md`는 repo 또는 사용자 단위의 지속 지침이다.

### 무엇을 제공하나

- 프로젝트 규칙
- 테스트/빌드 명령
- 코드 스타일
- 리뷰 기준
- 특정 디렉터리에서만 적용되는 작업 규칙

### 어떻게 주입되나

Codex가 작업을 시작할 때 instruction chain을 만든다.

```text
Codex 시작
→ global AGENTS.md 확인
→ repo root부터 현재 디렉터리까지 AGENTS.md 확인
→ 가까운 디렉터리의 지침이 뒤에 붙어 우선 적용
→ 합쳐진 지침이 LLM context에 들어감
```

### 특징

- LLM이 선택하는 것이 아니라 Codex가 세션 시작 시 자동으로 읽는다.
- 반복적으로 지켜야 하는 팀 규칙에 적합하다.
- workflow 자체가 복잡하면 Skill이 더 적합하다.

## Skills

Skill은 특정 작업을 잘 수행하기 위한 재사용 가능한 워크플로우 패키지다.

### 무엇을 제공하나

초기에는 가벼운 정보만 제공된다.

```text
- skill name
- description
- SKILL.md file path
```

Skill이 선택되면 다음 내용이 추가로 주입된다.

```text
- SKILL.md 본문
- 필요한 references
- 필요한 scripts 사용 지침
- workflow 단계
- 사용할 도구나 검증 절차
```

### 주입을 유발하는 이벤트

두 가지가 있다.

1. **명시적 호출**
   - 사용자가 `$skill-name` 형태로 직접 부른다.
   - 예: `$pptx 이 파일 요약해줘`

2. **암묵적 호출**
   - 사용자 요청이 skill description과 맞는다고 LLM 또는 Codex가 판단한다.
   - 예: 사용자가 "PR 리뷰해줘"라고 했고, review skill 설명이 그 요청과 일치하는 경우

### 동작 흐름

```text
사용자 요청
→ LLM은 사용 가능한 skill metadata를 봄
→ 적절한 skill 선택
→ Codex가 SKILL.md를 읽음
→ SKILL.md 내용이 context에 주입됨
→ LLM이 그 절차를 따라 작업
→ 필요하면 reference 파일을 읽거나 script/tool 실행
```

### 핵심

Skill은 도구라기보다 **늦게 주입되는 지침**이다. 모든 skill 본문을 항상 context에 넣지 않기 때문에 context 낭비를 줄인다.

## MCP

MCP, Model Context Protocol은 Codex가 외부 시스템의 도구와 데이터를 사용할 수 있게 하는 연결 방식이다.

### 무엇을 제공하나

MCP 서버는 보통 다음을 제공할 수 있다.

- Tools: 실행 가능한 기능
- Resources: 읽을 수 있는 데이터
- Prompts: 재사용 가능한 prompt template
- Server instructions: 서버 전체 사용 지침

### 항상 context에 들어가는가

아니다.

항상 들어가는 것에 가까운 것은 다음이다.

```text
- MCP 서버가 제공하는 tool 이름
- tool 설명
- input schema
- server instructions
```

항상 들어가지 않는 것은 다음이다.

```text
- GitHub 이슈 전체
- Figma 파일 전체
- Slack 채널 전체
- Google Drive 문서 전체
- DB 전체 데이터
```

실제 외부 데이터는 LLM이 tool을 호출한 뒤, 그 결과로 context에 들어간다.

### 동작 흐름

```text
Codex 시작
→ MCP server 설정 로드
→ MCP initialize
→ tools/resources/prompts/instructions 확인
→ LLM에게 tool schema 노출
→ LLM이 필요하다고 판단하면 tool call 생성
→ Codex MCP client가 서버에 요청
→ MCP 서버 결과가 tool result로 LLM context에 들어감
```

### 핵심

MCP는 **외부 기능을 LLM이 호출 가능한 tool로 노출**한다. LLM이 외부 시스템에 직접 접근하는 것이 아니라 Codex가 MCP client로 대신 호출한다.

## Hooks

Hook은 LLM이 직접 선택하는 도구가 아니다. Codex 런타임이 특정 lifecycle event를 만나면 자동으로 실행하는 스크립트다.

### 언제 실행되나

대표 이벤트는 다음과 같다.

- `SessionStart`
- `UserPromptSubmit`
- `PreToolUse`
- `PostToolUse`
- `PermissionRequest`
- `PreCompact`
- `PostCompact`
- `Stop`

### 동작 흐름

예를 들어 LLM이 Bash 실행을 선택하면:

```text
LLM: Bash tool call 생성
→ Codex: PreToolUse hook 확인
→ hook command 실행
→ hook 결과에 따라 허용/차단/입력 수정/추가 context 반영
→ Bash 실행
→ Codex: PostToolUse hook 실행
→ 최종 결과를 LLM에게 전달
```

### 무엇을 할 수 있나

- 위험 명령 차단
- API key 같은 민감정보 prompt 검사
- tool input 수정
- tool result 후처리
- 작업 종료 시 검증
- 대화 로그/분석 시스템 전송

### 핵심

Hook은 **LLM 바깥의 interceptor**다. LLM이 "hook을 실행하자"고 판단하는 것이 아니라 Codex 프로그램이 정해진 시점에 실행한다.

## Plugins

Plugin은 skill, MCP, app integration, hook 등을 묶어서 설치하고 배포하는 단위다.

### 무엇을 제공하나

Plugin 자체가 하나의 LLM tool인 것은 아니다. Plugin 안에 들어 있는 구성요소가 각각 등록된다.

```text
Plugin 설치
→ 포함된 Skills 등록
→ 포함된 MCP servers 등록
→ 포함된 app connectors 등록
→ 포함된 Hooks 등록
→ 새 thread에서 기능 사용 가능
```

### 용도

- 팀이나 개인에게 재사용 가능한 workflow 배포
- 여러 skill을 한 번에 설치
- skill과 MCP 설정을 함께 제공
- app connector와 인증 흐름을 묶어 제공
- lifecycle hook까지 포함한 개발 환경 표준화

### 핵심

Plugin은 **기능 자체라기보다 배포 형식**이다.

## Memories

Memories는 이전 thread에서 얻은 안정적인 정보를 이후 작업에 다시 사용하는 기능이다.

### 무엇을 제공하나

- 사용자 선호
- 반복되는 workflow
- 자주 쓰는 기술 스택
- 프로젝트 관례
- 과거에 발견한 함정

### 어떻게 주입되나

```text
이전 thread 종료 후 충분히 idle
→ Codex가 유용한 정보를 memory로 추출
→ memory 파일에 저장
→ 이후 thread에서 관련 memory를 context에 주입
```

### 특징

- 기본적으로 꺼져 있을 수 있다.
- team rule처럼 반드시 지켜야 하는 내용은 memory보다 `AGENTS.md`에 두는 것이 낫다.
- memory는 보조적인 recall layer다.

## Rules, Permissions, Sandbox, Approvals

이 계층은 LLM에게 지식을 주입하기보다는, Codex 런타임이 행동을 허용하거나 차단하는 정책에 가깝다.

### 구성 요소

- Sandbox: 파일시스템/네트워크 접근 범위 제한
- Approvals: 특정 행동 전에 사용자 승인 요구
- Rules: 특정 command prefix를 allow/prompt/forbidden 처리
- Permissions: 사용할 수 있는 기능과 접근 범위 설정

### 동작 흐름

```text
LLM이 command/tool call 제안
→ Codex가 sandbox와 rules 확인
→ 허용 가능하면 실행
→ 승인이 필요하면 approval 요청
→ forbidden이면 차단
```

### 핵심

이 계층은 **LLM의 의도와 실제 실행 사이의 안전장치**다.

## Subagents

Subagent는 별도의 LLM 세션을 생성해서 작업을 나누는 방식이다.

### 무엇을 제공하나

- 다른 instruction
- 다른 model 설정
- 다른 reasoning effort
- 다른 sandbox 설정
- 다른 MCP/skill 설정
- 역할별 전문화

### 동작 흐름

```text
사용자가 subagent 사용을 명시 요청
→ Codex가 하위 agent thread 생성
→ 각 subagent가 독립적으로 도구와 context 사용
→ 결과를 parent agent가 모음
→ 최종 요약 또는 통합 결과 반환
```

### 용도

- 큰 PR을 여러 관점으로 리뷰
- 코드베이스 탐색을 병렬화
- 구현/테스트/문서화 역할 분리
- 조사 agent와 실행 agent 분리

### 핵심

Subagent는 같은 LLM context를 조금 확장하는 것이 아니라 **별도 agent run을 만드는 방식**이다.

## Automations

Automation은 정해진 시간이나 주기에 Codex 작업을 자동 실행하는 기능이다.

### 무엇을 제공하나

- 예약된 prompt
- 반복 실행 cadence
- 프로젝트 또는 thread 범위
- 필요 시 skill/plugin 사용

### 동작 방식

```text
사용자가 automation 생성
→ schedule 저장
→ 정해진 시간에 Codex가 wake-up
→ prompt 실행
→ 결과가 thread 또는 triage inbox에 쌓임
```

### 종류

- Thread automation: 기존 thread를 주기적으로 깨움
- Standalone automation: 독립적인 새 run을 주기적으로 실행
- Project automation: 특정 프로젝트에서 반복 작업 실행

### 용도

- PR 상태 주기 확인
- 배포 완료 여부 polling
- 매일 lint/test 상태 점검
- 정기 security scan
- Slack/GitHub 상태 확인

### 핵심

Automation은 **에이전트를 시간축에 연결하는 운영 계층**이다.

## Custom Prompts

Custom prompt는 Markdown 파일을 slash command처럼 호출해서 prompt text로 확장하는 방식이다.

### 동작 흐름

```text
사용자가 /prompts:name 호출
→ prompt 파일 내용 로드
→ placeholder 치환
→ 확장된 텍스트가 사용자 prompt처럼 전송
```

### 특징

- 명시적 호출이 필요하다.
- Codex에서는 deprecated이며, 재사용 workflow는 Skill을 권장한다.
- 단순 prompt template에는 여전히 개념적으로 유용하다.

## App Connectors와 Browser/Computer Use

Codex에는 MCP 외에도 app connector나 browser/computer use 같은 외부 행동 표면이 있을 수 있다.

### App Connectors

GitHub, Slack, Google Drive 같은 서비스에 인증된 연결을 제공한다. MCP와 비슷하게 외부 데이터와 action을 제공하지만, 제품 내 connector 권한과 인증 흐름을 따른다.

### Browser Use

Codex가 브라우저를 열고 웹 UI를 조작하거나 검사할 수 있게 한다. 웹 검색, 브라우저 자동화, UI 테스트와 연결된다.

### Computer Use

Codex가 데스크톱 앱이나 OS UI를 조작할 수 있게 하는 더 넓은 실행 표면이다. 파일 편집이나 shell command와는 별도의 시스템 권한과 app approval이 관련된다.

## 개념 간 관계

가장 간단한 관계도는 다음과 같다.

```text
AGENTS.md / Memories / Skills
= LLM에게 "무엇을 알고 어떻게 행동할지" 제공

MCP / Apps / Browser / Shell / File tools
= LLM이 호출할 수 있는 "행동 수단" 제공

Hooks / Rules / Sandbox / Approvals
= LLM 바깥에서 실행을 감시하고 통제

Subagents / Automations
= 에이전트를 여러 개 쓰거나 시간에 따라 실행

Plugins
= 위 요소들을 묶어서 설치/공유
```

## 선택 기준

| 하고 싶은 일 | 적합한 표면 |
|---|---|
| repo 규칙을 항상 따르게 하기 | `AGENTS.md` |
| 반복 workflow를 재사용하기 | Skill |
| 외부 시스템의 데이터를 읽거나 action 실행하기 | MCP 또는 app connector |
| tool 실행 전후에 정책 검사하기 | Hook |
| 여러 기능을 설치 가능한 패키지로 배포하기 | Plugin |
| 이전 대화의 안정적 맥락을 기억하기 | Memories |
| 위험 명령을 막거나 승인 요구하기 | Rules/Permissions/Sandbox |
| 큰 작업을 여러 역할로 나누기 | Subagents |
| 정기적으로 작업을 실행하기 | Automations |
| 단순 prompt template을 빠르게 호출하기 | Custom prompts |

## 핵심 요약

- **Skill**은 선택되면 context에 늦게 주입되는 작업 매뉴얼이다.
- **MCP**는 외부 도구를 LLM이 호출 가능한 tool schema로 노출한다.
- **Hook**은 LLM 바깥에서 Codex가 특정 이벤트 전후에 자동 실행한다.
- **Plugin**은 skill, MCP, app, hook을 묶어 설치/공유하는 배포 단위다.
- **AGENTS.md**는 세션 시작부터 적용되는 지속 지침이다.
- **Memory**는 과거 작업에서 추출한 보조 맥락이다.
- **Rules/Permissions**는 실제 실행을 통제하는 안전장치다.
- **Subagent**는 별도 LLM 세션으로 역할을 나누는 방식이다.
- **Automation**은 에이전트를 시간에 따라 다시 실행하는 운영 기능이다.
